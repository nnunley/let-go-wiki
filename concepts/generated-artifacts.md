# Generated Artifacts

The runtime does not compile `core.lg` at startup. It loads committed artifacts generated from the `.lg` sources, and a Go build cannot regenerate them: Go has no build-time codegen hook, so an edit under `pkg/rt/core/` has no effect until `make generate` runs. Everything on this page exists to make that fact safe: a manifest that says which artifact is stale, gates that refuse to build or commit against a stale one, and a build tag that lets the generator compile core from source without trusting the bundle inside the binary that runs it.

## The outputs

`pkg/rt/generated.manifest` declares seven outputs. Six are committed; the lowered Go tree is gitignored and rebuilt locally. Each is regenerated by a stage of `scripts/generate.lg`, run as `make generate`. `make generate` depends on `make build`, which promotes the candidate `build/lg` to `bin/lg` after `smoke` passes. The recipe then runs `scripts/generate.lg` with the candidate `build/lg` (passed as `--lg`) and the resolved `go`; the promoted `bin/lg` is not the binary that runs the script.

| Output | Generated from | Loaded by |
|---|---|---|
| `pkg/rt/core_compiled.lgb` | every embedded `.lg` under `pkg/rt/core/`, compiled by `cmd/lgbgen` | the default runtime, at boot (see [runtime image](runtime-image.md)) |
| `pkg/rt/core_go_lowered/` (gitignored) | the same sources, lowered to Go by `cmd/lgbgen --target=go` | builds with `-tags gogen_ir` (see [compile paths](compile-paths.md)) |
| `pkg/ir/op_generated.go` | `pkg/ir/ir_ops.lg` via `scripts/generate.lg` | the Go side of the [IR](indexed-rpn-ir.md): op table and catalog |
| `pkg/rt/ir_bridge_generated.go` | `pkg/ir/ir_bridge.lg` | the Go bridge primitives the [IR pipeline](ir-pipeline.md) calls |
| `pkg/rt/core/ir/data/generated.lg` | `pkg/ir/ir_data.lg` | the IR data accessors, on the Lisp side |
| `pkg/rt/zz_primitives_generated.go` | `//lg:native` annotations in `pkg/rt` via `cmd/lgprimgen` | the runtime's own primitive registrar (see [native primitives](native-primitives.md)) |
| `pkg/rt/corefns/zz_primitives_generated.go` | annotations in `pkg/rt/corefns` | the contribute-mode registrar |

The [regeneration doc](https://github.com/nooga/let-go/blob/main/docs/regenerating-generated-artifacts.md) describes only the two core artifacts (the bundle and the lowered tree). The manifest and `scripts/generate.lg` cover all seven outputs in the table above.

The three IR generators run in process: `generate.lg` `load-string`s each `.lg` generator, capturing stdout with `with-out-str` for the op and bridge tables and writing the return value of the data generator's final form, because shelling out to a second `lg` dropped trailing bytes nondeterministically. It shells out to `lgprimgen` for the two registrars and once to `go run -tags bootstrap ./cmd/lgbgen --target=both`, one core compile feeding both the bundle and the lowered tree so the untagged and `gogen_ir` runtimes cannot drift apart.

## Staleness is content, not time

Make prerequisite rules and the older `check-*-fresh` targets compare modification times. At b82588292b `check-lowered-fresh` still does so (`find pkg/rt/core -name '*.lg' -newer pkg/rt/core_go_lowered/ir/lower_go/lower_go.go`). Modification times are unreliable after a `git` or `jj` checkout: the VCS writes arbitrary times, so a stale bundle can look newer than the source that should have rebuilt it. `pkg/genmanifest` hashes content instead.

The manifest is a list of edges, one per line: `<output> <input> <kind> <sha256>`, where `kind` is `input` (a domain source such as `ir_ops.lg`), `generator` (a file of the generator's own implementation), or `output` (the declared output's last generated bytes). `pkg/rt/generated.sums` holds a single digest of the manifest; `make check-generated-manifest` compares it. Generator edges come from `go list -deps -json -tags bootstrap ./cmd/lgbgen`, run with `GOOS=linux GOARCH=amd64 CGO_ENABLED=1` and the toolchain pinned from `go.mod`, so a change to the bytecode encoder or the compiler counts as a reason to regenerate the bundle. The package expansion walks imports through every platform and tag variant and records all package-local build sources except `_test.go` files, so the manifest does not depend on the host that ran the query (#641).

Two separate questions are asked of it:

- **Are the inputs fresh?** A recorded input or generator digest that differs from the file on disk means someone edited a source without regenerating.
- **Is the output ready?** For a file output, do its bytes still match the recorded output edge. For the lowered tree, `CheckTreeManifest` passes: the sentinel `.lgbgen-tree.sum` exists and every file it lists has its recorded sha256. Unlisted files are tolerated. `cmd/lgbgen` writes the sentinel as the last step of a successful install and deletes it first on reinstall, so a crash mid-install can never leave a valid sentinel over a torn tree.

`make generate` reruns only stages whose inputs changed or whose outputs are disturbed, and requeries staleness after the IR generators run so a change that propagates into `lgbgen`'s inputs is picked up in the same pass. A staleness query that fails is an error, not an empty clean set.

## Where a stale artifact is caught

| Gate | What it does |
|---|---|
| `make check-generated-manifest` | non-mutating front gate: runs `cmd/check-generated` and fails on a manifest mismatch, so no target can refresh the digest first |
| `make check-generated` | runs `scripts/check-generated.sh`: saves the six committed outputs and `generated.sums`, runs the full `make generate`, and `cmp`s the six outputs (both registrars, the IR op and bridge files, `ir/data/generated.lg`, `core_compiled.lgb`) against the saved copies. It then builds `-tags gogen_ir ./pkg/rt/...` and checks that `ir.passes.dce/dce` dispatches to a `NativeFn`. It restores the saved files on exit, on success or failure, so the working tree is left as it was found. It does not run the manifest gate. |
| `go test ./...` | `TestGeneratedArtifactsAreFresh` in `pkg/genmanifest` fails when a source changed without `make generate` |
| pre-commit hook | `scripts/pre-commit` runs `go run ./cmd/check-generated` and refuses the commit on failure once it is symlinked into `.git/hooks/`; no make target installs it. `jj` runs no git hooks, so `jj` users rely on the test and the make target |
| merge drivers | `make install-hooks` registers `merge.lgb` and `merge.sums`, which regenerate `core_compiled.lgb` and recompute `generated.sums` after the `.lg` sources have merged as text, so a rebase that touches `core.lg` does not end in a binary conflict |

The merge drivers live in `.git/config`, registered by `make install-hooks`; the pre-commit hook is a manual symlink into `.git/hooks/`. Neither is shared, so each clone sets them up once.

## The bootstrap tag

`cmd/lgbgen` is built with `-tags bootstrap`. Under that tag `pkg/rt/core_embed_bootstrap.go` replaces the `//go:embed core_compiled.lgb` in `core_embed.go`, so the generator compiles core from source and never consults the bundle embedded in whatever `lg` is running the build. A stale embedded bundle therefore cannot taint regeneration. `scripts/generate.lg` itself runs on `build/lg`, the candidate binary that `make build` produces, and shells out to the bootstrap build for the one heavy stage; without the tag `cmd/lgbgen` is a stub that exits with status 2.

The embedded-core tree (`//go:embed all:core` in `pkg/rt/core_embed_fs.go`) is also the universe the self-hosting bootstrap walks when it derives the Go-lowering order, topologically sorting every `(ns ...)` by its `:require` edges plus one synthetic edge: `ir.build` must load after every optimization and inference pass, because the passes register state at load time and lowering before that state exists emits untyped arithmetic. Adding a source to that tree changes what the bootstrap lowers.

`gogen`, the Go-emission macro layer the AOT path requires, sits outside that tree. It is embedded from `pkg/rt/gogen/gogen.lg` by a separate `//go:embed` in `pkg/rt/gogen_src.go` and registered as an auxiliary embedded source (#425, #557), so a shipped `lg` can `(require 'gogen)` from any working directory. The embed is not gated on `!bootstrap`: `gogen_src.go` has no build tag, and its comment states that it is embedded under `-tags bootstrap` as well, because `lg.compiler` requires `gogen` when lgbgen lowers it. Auxiliary sources are absent from `EmbeddedNSNames`, which walks `core/` only, so `gogen` is never precompiled into the bundle and never lowered itself. The source comment ties this placement to the lowering fixpoint: enrolling `gogen` under `core/` would perturb the interpreted-vs-native fixpoint checked by `TestLoweringDeterminism`. Issue #786 describes `gogen` as registered behind `!bootstrap`; at b82588292b the source does not match that description.

The compiler orchestration namespace `lg.compiler` is different: its source is `pkg/rt/core/lg/compiler.lg`, so it is in the `core/` walk and enrolled in `EmbeddedNSNames` with no auxiliary embed. `lgbgen` excludes `lg.compiler` and its descendants from the bundle (`isBundleSkippedTool`). The decision recorded for PR #735 on 2026-09-02, as Norman states it, is that `lg.compiler` enrolls in the standard embedded and generated set immediately with no temporary auxiliary embed. His proposal in #786 names moving `gogen` into the bootstrap universe as a later step, and says that step must first resolve the cold/hot lowering fixpoint rather than simply enroll the file.

## Working with them

- Edit anything under `pkg/rt/core/**/*.lg`, `pkg/ir/ir_*.lg`, or an annotated Go primitive, then `make generate` and commit the regenerated committed outputs (bundle, sums, manifest, registrars, IR tables) with the change; the lowered tree stays local. `make check-generated` before pushing.
- A PR that regenerates `core_compiled.lgb` or `generated.sums` will conflict with any other such PR on rebase; regenerate after the text merge rather than resolving the binary or the digest by hand.
- `go generate ./cmd/lgbgen` runs the two `//go:generate` directives (bundle, then `--target=go`); prefer `make generate`, which also runs the IR generators and the registrars and passes the exact resolved `go` and `lg`, recording both in a local provenance file (`pkg/rt/generated.provenance`, gitignored) and reporting `lg` version drift from the previous run in the build log (the Go version is recorded but not compared).
