# Go Backend

The design in `docs/design/go-aot-backend.md` proposed two tiers: embed bytecode as Go data, then lower functions to real Go. What shipped is the second tier, on the [IR pipeline](ir-pipeline.md): `ir.lower-go` turns an optimized IR function into Go source that keeps the runtime's `Value` and `Var` model, so lowered code and interpreted code call each other through the same vars and dynamic `eval` keeps working. This page is about that shipped backend; [lg-compile](lg-compile.md) covers the whole-program driver's command line, and [compile paths](compile-paths.md) where the backend sits relative to the other two.

## What the lowering produces

Each lowered `defn` becomes a Go function whose first parameter is the `*vm.ExecContext` and whose remaining parameters and result are either `vm.Value` or a Go type that [type inference](type-inference.md) proved (`int64`, `float64`, `bool`, `string`, and since #1057 `*vm.TypedArray` for an array whose element kind is declared; see [typed arrays](typed-arrays.md)). A let-go `:int` lowers to `int64` on every host, not to host-width `int` (#862): on a 32-bit target the two disagree, and `vm.Int` is itself `int64` since #859. Host-width `int` survives only where a [native primitive](native-primitives.md) declares such a parameter itself. Block-parameter control flow from `structurize` becomes mutable locals with labels and gotos; arithmetic on proven types stays unboxed, including operators written `clojure.core/+` or `core/<`, the form syntax-quote emits, which build as builtin ops since #1060 (before it, every macro-written operator, `dotimes` counters included, lowered as a var call); self-recursion (`:recur-fn`) lowers to a labelled loop. #649's `TAIL_CALL` fusion is a bytecode-lowerer optimization with no counterpart here. The header of `lower_go.lg` lists the supported ops and the two modes: strict, where an unsupported op or shape throws, and bridge, where an unsupported function falls back at whole-function granularity and stays on bytecode.

Source text is not built with string templates. The `gogen` namespace constructs `go/ast` nodes from let-go: a `(gquote (func ...))` form expands at macro time into constructor calls, those evaluate to boxed AST nodes, and `gogen/render` prints them with `go/format.Node`, so every generated file is gofmt-canonical. `gogen` is embedded in shipped binaries as an auxiliary source outside the core lowering universe (#557); see [generated artifacts](generated-artifacts.md) for why it must stay outside.

## Direct calls and the trampoline

The point of the backend is that lowered code can call other lowered code, and native primitives, as plain Go calls. Whether a function qualifies is decided per function:

- **Direct-callable** (`override-coercible?` in `lower_go.lg`): non-variadic, and every parameter and result type is one a call site can coerce soundly. A typed sibling such as `func F(ec, x int64) int64` is recorded with its actual specs, so a caller with a proven-`:int` argument emits `F(ec, intval)` with no boxing; a caller that cannot prove the type falls back to the trampoline for that call. Because one Go type, `*vm.TypedArray`, stands for every array kind, entries also record lattice `:param-types` beside the Go `:param-specs` (#1057): a proven array of the declared kind passes through, a different kind or a proven non-array takes the trampoline, and an unproven `vm.Value` is guarded with a kind check.
- **Override-eligible**: the shape that gets an override wrapper registered on the var, so interpreted code calling the var lands on the Go function: uniform `vm.Value` in and out, or `vm.Value` parameters with a primitive return the wrapper can box (`bool`, `int64`, `float64`, `string`, `vm.Char`). #862 re-spelled that list too: it mirrors `box-as-value`'s constructor set, which routes `int64` to `vm.Int` and carries no host-width `int` case.

Everything else, variadic functions above all, goes through the trampoline. A cross-namespace callee is emitted as `ec.Invoke(rt.CachedVarFnEC(ec, &__v_…, "ns", "name"), args…)`: the callee var is resolved once through a package-level pointer, then dereferenced through `ec` on each call, so a `^:dynamic` binding in the running context (a future's included) selects the callee. Since #1003, a call with one to four arguments passes them as parameters (`ec.Invoke1` to `ec.Invoke4`, or `rt.InvokeValueEC1` to `InvokeValueEC4` when the callee is not a recorded var), so no argument slice is built at the call site. Zero or five-plus arguments still build a `[]vm.Value` literal. The choice at the call site depends only on argument count (`invoke-by-arity`, `trampoline-call-stmts` in `lower_go.lg`), not on whether the callee is variadic, so a variadic callee reached with one to four arguments still emits `Invoke1`–`Invoke4`; those fall back to the slice path inside `pkg/vm/invoke_arity.go` when the callee has no arity-typed method. The call is still a var lookup and a dynamic dispatch. The per-namespace direct-call registry is seeded from the [native primitive](native-primitives.md) registry and from lowered siblings, and `lower-all-ns-to-go` merges every package's exports into a cross-package registry so a call into another lowered package resolves to `pkg.LG_<name>(ec, ...)` with the matching import. A `^:dynamic` or `^:redef` defn is never entered in that registry (#1017): its callers reach it through the var, as Clojure's direct linking does, so a `binding` or `with-redefs` on it takes effect at once. Ordinary siblings stay direct-linked, so a `with-redefs` on one reaches its lowered callers only after recompilation.

One escape hatch keeps direct calls honest: `*direct-calls-disabled?*`, bound at lowering time, forces every call through the trampoline so runtime `alter-var-root` overrides are observed. `pkg/vm` also maintains a process-wide deviation counter for guarded native-primitive vars (`GuardedRootsIntact`), but at `0911118` only the `rt/native-prims-intact?` diagnostic reads it; emitted call sites do not consult it (see [namespaces and vars](namespaces-and-vars.md)).

## Two deployments

**The core.** `make generate` lowers the embedded core into `pkg/rt/core_go_lowered/` (gitignored), and a build with `-tags gogen_ir` links it: each lowered package's `init` queues overrides, and the runtime applies them onto the vars after each namespace loads from bytecode. `bench-ratchet` measures both variants, and the [ratchet doc](perf-ratchet.md) is candid that lowered core code still boxes most cross-namespace calls, so it can allocate more than bytecode; direct-call coverage is the lever.

**Programs.** `./lg scripts/lg-compile [--entry-frame] <out-dir> <import-prefix> <file.lg>...` lowers a set of files to one Go package per namespace with direct calls wired between them. That script is the compatibility shim; the orchestration it wraps lives behind `lg.compiler` at `pkg/rt/core/lg/compiler.lg` (#735, merged 2026-09-10, revised to Norman's decision on the still-open #786). The driver is embedded in every binary, so a shipped `lg` drives lowering with no let-go checkout on disk. With `--entry-frame` it also emits `main.go`, the native-entry frame from `passes/entry_frame.lg`: publish `*command-line-args*`, decode the program bundle, load its namespaces (draining overrides after each), replay the main chunk once so top-level forms and VM-backed vars exist, drain the namespace that chunk entered (#1010), then call the lowered entry. Core is not booted by the frame itself. The frame blank-imports `pkg/compiler`, whose `init` replays the core bundle and installs `eval`, `load-string`, and the other compiler-backed vars (#1008; `emit-boot-stmts` in `entry_frame.lg`). It also installs a namespace resolver, so a run-time `require` loads namespaces from the bundle, from core, or from `LG_SOURCE_PATHS` when that is set (which then fully defines the search path), and, when `LG_SOURCE_PATHS` is unset, never from the working directory (`passes/entry_frame.lg`, `emit-boot-stmts`). The entry is `main` or `-main` with arity `[]`, `[argv]`, or `[& args]`; other shapes fail generation with a source-level diagnostic. The shipped `lg compile` (#977) runs the same lowering through `lg.compiler` and then does the steps this script leaves to its caller: it writes `program.lgb` through a child `lg -c -entry-frame-entry` run, scaffolds `go.mod`, and runs `go build` itself (`pkg/cli/compile.go`). With a caller-supplied module it passes `-mod=readonly` (#1016), and `-import` (#1037) links Go packages into such a build. Outside `lg compile`, the orchestrator (gloat, or a Makefile) owns `go.mod`, `go build`, and placing `program.lgb` beside `main.go`. `examples/aot/native-entry` builds `fib` and `-main` this way and reports about 16 times the VM's speed on `fib(34)`.

## The runtime-only binary

`cmd/lg-runtime` executes precompiled bytecode with no reader, compiler, or resolver linked in; the guarantee is structural, enforced by a test that the package never imports `pkg/compiler` or `pkg/resolver`, so there is no `eval`, `read-string`, or dynamic source `require`. Entry-frame binaries are the contrast: their frame links `pkg/compiler` and `pkg/resolver` (see [Programs](#two-deployments)), so they do carry `eval`, `load-string`, and run-time `require`. `lg -b myapp -bundle-base lg-runtime app.lg` appends a program to a copy of it for a standalone, compiler-free bundle. It also loads a split debug companion beside the artifact (see [`.lgb` format](lgb-bytecode-format.md)). `-tags lg_no_http` (#658) drops `net/http` and the TLS and x509 packages behind it, which the linker could never prove unused because the HTTP namespace registers from an `init`; on darwin/arm64 that cut `lg-runtime` from 17.6 MB to 12.2 MB. A build tag is the stopgap; the direction Norman set on #652 (2026-07-31) is a tree-shaker driven by the AOT that decides which runtime subpackages link, with dead-code elimination surfacing the dependencies as it generates imports, once the interop consolidation lands.

## Gates and open defects

`make native-entry-gate` (#729) proves that lowered entries execute as generated Go rather than through a silent fallback. #959 deprecated the target: at `b82588292b` its recipe prints a notice recommending `make test SHORT=false PKG=./test/e2e RUN="TestNativeEntryASTGate|TestJankSuiteDirectABIGeneratedGo"` as the command to use going forward, while the recipe itself still runs `go test` directly with the same `-run` pattern (Makefile, `native-entry-gate` target, lines 397–400). Each fixture under `test/native-entry/` carries an exact `.expect` stdout and a structural `.goexpect.json` contract, and a missing sidecar fails rather than skips. Building the gate found a real defect: for a single-file program `lg -c` emits a bundle with an empty namespace table, so the frame's namespace load ran nothing and every namespace-level var stayed undefined, which only worked while every reachable callee lowered to a direct call. The frame now runs the main chunk after loading namespaces, idempotently.

#783 was open at 2026-09-05 and closed 2026-10-06. A lowered function whose own inline lambda is lambda-lifted (`mapv (fn [f] (f)) fs`) emits `ec.Deref(rt.LookupVar(ns, "fn__lifted0"))`, and in an entry-frame binary that var was nil at first deref, so the binary panicked where the VM runs the same program. The cause was the same empty-namespace-table path: the lifted var's override was queued but never drained before use. #1010 fixed it: `RunProgramMainChunk` (`pkg/rt/run.go`) now drains the namespace the main chunk entered, after the chunk runs, and only that one, so a namespace that exists only as decode stubs is not replayed over its drained overrides. Also #607, an AOT bundle rejected by its own runtime over a capability-mask mismatch, tracked separately. #796 was the third: the main-chunk replay that fixed the empty-namespace-table defect also ran a program's top-level forms, so the documented `(when-not *compiling-aot* (-main))` guard from `docs/guide/usage.md` fired on the VM before the frame called the lowered entry, and such a program ran twice, once interpreted and once native. #902 closed it in v1.13.0 by adding `lg -c -entry-frame-entry ns/-main`, which omits the selected top-level entry call from the bytecode because the native frame calls it; `*compiling-aot*` stays false at runtime, so guarded initialization in required namespaces still runs.
